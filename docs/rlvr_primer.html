0Prerequisites

You need four tools, nothing more.

  • Bernoulli and binomial distributions. A prompt the model solves with probability $p$ is a coin flip. Sampling $G$ answers gives $\text{Binomial}(G,p)$ correct ones.
  • Gradients and SGD. $\theta \leftarrow \theta + \eta \cdot \widehat{\nabla J}$, where $\widehat{\nabla J}$ is a noisy estimate of the gradient.
  • Softmax. $\pi(k) = e^{\ell_k} / \sum_j e^{\ell_j}$. The one derivative to know: $$\frac{\partial \log \pi(k)}{\partial \boldsymbol{\ell}} = \mathbf{e}_k - \boldsymbol{\pi}.$$ In words: raise logit $k$, and lower every logit in proportion to its probability.
  • KL divergence. $\mathrm{KL}(\pi \,\|\, \pi_{\text{ref}}) = \sum_y \pi(y) \log \frac{\pi(y)}{\pi_{\text{ref}}(y)}$ measures how far the trained policy has drifted from where it started.

1RL as an optimization problem

A policy $\pi_\theta(y \mid x)$ is a distribution over responses $y$ given a prompt $x$. A reward $r(x,y)$ scores each response. We maximize the expected reward:

$$J(\theta) = \mathbb{E}_{x}\, \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)} \big[ r(x,y) \big].$$

The obstacle: you cannot backpropagate through sampling. $r$ is just a number, not a differentiable function of $\theta$. The log-derivative trick gets around this:

$$\nabla J = \sum_y r(y)\, \nabla \pi(y) = \sum_y \pi(y)\, r(y)\, \nabla \log \pi(y) = \mathbb{E}_{y \sim \pi}\big[\, r(y)\, \nabla \log \pi(y) \,\big].$$

So: sample $y$, look at its reward, and push $\log \pi(y)$ up in proportion to $r$. That is REINFORCE. It is unbiased but very noisy.

Baselines and advantages

For any $b$ that does not depend on $y$, $\mathbb{E}[\, b\, \nabla \log \pi(y)\,] = b \sum_y \nabla \pi(y) = b\, \nabla 1 = 0$. So we can subtract a baseline without adding bias, and use the advantage $A = r - b$ instead of $r$. With $b \approx$ the average reward, the variance drops dramatically. The intuition is to raise the probability of better-than-average samples and lower that of worse-than-average ones.

The single most important fact for this project: if every sample in a batch gets the same reward, then $A = 0$ for all of them and you learn nothing.

2An LLM is just a policy

A response is a sequence of tokens $y = (y_1, \dots, y_T)$, so

$$\log \pi(y \mid x) = \sum_{t=1}^{T} \log \pi(y_t \mid x, y_{<t}).$$

Two consequences matter here.

  • No per-token credit. The reward arrives only at the end, so every token in a response gets the same advantage.
  • Length scales the gradient. The score $\nabla \log \pi(y)$ is a sum of $T$ terms, so its size grows with the length $T$. Implementations must choose between summing over tokens and averaging ($\tfrac{1}{T}\sum_t$). This is the root of the step-size story in Section 6.

3Verifiable rewards (RLVR)

Instead of a learned reward model, a program checks the answer: the final number matches, or the unit tests pass. DeepSeek-R1 adds a small format reward (reasoning inside <think> tags), but the core signal is binary: $r \in \{0, 1\}$.

  • Upside: the reward cannot be “hacked” the way a neural reward model can.
  • Downside: the reward is sparse. On a given prompt, only the success rate $p$ matters, and if $p \approx 0$ there is nothing to learn from.

Two metrics follow:

$$\text{pass@1} = p, \qquad \text{pass@}k = 1 - (1-p)^k \;\;\text{(at least one of } k \text{ answers is right).}$$

4From PPO to GRPO

PPO learns the baseline with a second neural network (a critic), which is expensive for LLMs. GRPO instead samples $G$ answers to the same prompt and uses the group itself as the baseline:

$$A_i = \frac{r_i - \operatorname{mean}(r_1, \dots, r_G)}{\operatorname{std}(r_1, \dots, r_G)}.$$
  • Ratio clipping only matters when you take several gradient steps on the same batch. With fully on-policy training (one step per batch) the probability ratio is 1 and clipping does nothing, which is why the project ignores it.
  • A KL penalty $\beta\, \mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})$ keeps the model near its starting point.

The variants the project compares differ only in the advantage:

VariantAdvantage $A_i$Notes
GRPO$(r_i - \bar r) / \text{std}$Dividing by the std rescales each prompt by $1/\sqrt{p(1-p)}$
Mean-only (Dr. GRPO)$r_i - \bar r$No std; Dr. GRPO also drops the per-length averaging
RLOO$r_i - $ mean of the other $G-1$Baseline independent of sample $i$, so exactly unbiased
Pass@$k$GRPO advantage × leave-one-out weightsOptimizes pass@$k$ instead of pass@1

A subtle point. $\bar r$ includes $r_i$ itself, so mean-only quietly shrinks the update by a factor $(G-1)/G$. RLOO avoids that. This is exactly the finite-$G$ effect captured by Proposition 1 in the proposal.

5The playground

main.py runs GRPO on the smallest possible RLVR problem: one question, $K$ possible answers, one of them correct. The policy is a softmax over $K$ logits that starts uniform, so $p_0 = 1/K$, and the success probability is known exactly at every step. The core loop is:

pi = softmax(logits)
y = rng.choice(K, size=G, p=pi)          # sample a group of G answers
r = (y == correct).astype(float)         # the verifier
A = advantages(r, kind)                  # grpo / mean / rloo / passk
grad = mean_i A_i * (onehot(y_i) - pi)   # A * d log pi(y_i) / d logits
logits += lr * grad                      # one SGD step

Run it from a terminal in the repo root, with the project's Python environment active:

python main.py                           # GRPO, K=8, G=8
python main.py --help                    # every option
python main.py -K 1000 -G 16             # sparse reward: p0 = 0.001
python main.py --advantage mean          # Dr. GRPO
python main.py --beta 2 -n 6000 --lr 0.2 # KL penalty; prints predicted p*
python main.py --advantage passk -k 8 -G 16

Each progress line shows the exact success probability, the running fraction of steps whose group was informative (not all-equal), and the policy entropy. When $\beta > 0$ it also prints the fixed point predicted by Proposition 1. The numbers quoted below come from the default seed; other seeds differ somewhat.

6Four phenomena the project tests

(a) Most groups can be useless — E1

A group gives zero gradient when all its answers agree, which happens with probability $p^G + (1-p)^G$. The fraction of informative groups is

$$\phi(p, G) = 1 - p^G - (1-p)^G \;\approx\; G\,p \quad \text{for small } p.$$

At $p = 0.01$ and $G = 8$, only about 8% of groups carry any signal. Even with exact gradients, Suk & Duan show $\nabla J = p(1-p)\,(g^+ - g^-)$, where $g^{\pm}$ is the average score of correct and incorrect answers. Learning is slow at both ends, $p \approx 0$ and $p \approx 1$. Bigger $G$ helps exactly when $p$ is small; the open question is when that is worth the compute.

Try it 
python main.py -K 1000 -G 2  -n 1000 --print-every 250
python main.py -K 1000 -G 16 -n 1000 --print-every 250
python main.py -K 1000 -G 64 -n 1000 --print-every 250

Starting from $p_0 = 0.001$: after 1000 steps, $G = 2$ has only reached $p \approx 0.003$. $G = 16$ sits near $p_0$ for a few hundred steps and then shoots to $p \approx 0.99$ by step 500. $G = 64$ reaches $0.82$ by step 250. The slow start is the regime where almost every group is all-wrong.

(b) Success amplification — E2 (Mroueh)

Combine the std-normalized advantage with a KL penalty and ask where training settles. The answer is a fixed point $p^\ast$ that is always above the starting success rate $p_{\text{ref}}$: GRPO amplifies success. In logit form, for a group of size $G$,

$$\operatorname{logit} p^\ast = \operatorname{logit} p_{\text{ref}} + \frac{\Omega_G(p^\ast)}{\beta},$$

where $\Omega_G = (G-1)/G$ for mean-only, $\Omega_G = 1$ for RLOO, and for GRPO $\Omega_G(p)$ is roughly $1/\sqrt{p(1-p)}$ when $G$ is large. GRPO's weight is at least about 2, so it amplifies more than mean-only. The proposal's Proposition 1 gives the exact finite-$G$ version, and shows that SGD and Mroueh's idealized iteration share these fixed points but can behave differently when rewards are sparse.

Try it 
python main.py --advantage mean --beta 2 --lr 0.2 -n 6000 --print-every 3000
python main.py --advantage rloo --beta 2 --lr 0.2 -n 6000 --print-every 3000
python main.py --advantage grpo --beta 2 --lr 0.2 -n 6000 --print-every 3000

With $K = 8$, $G = 8$ and $\beta = 2$ the predicted fixed points are 0.181, 0.191 and 0.279, and the runs end at 0.189, 0.199 and 0.29. The ordering and the size of each value match the prediction. Each reading is a single noisy snapshot; a smaller --lr reduces the jitter.

(c) Step-size thresholds — E3 (Suk & Duan)

The theory says that with exact gradients there is a step size above which training can overshoot and performance can fall instead of rise. Because the gradient magnitude scales with the response length $T$, the safe step size scales roughly as $1/T$. That is why averaging over tokens stabilizes training. The project tests whether a sharp threshold actually shows up with noisy gradients and a neural network.

Try it 
python main.py --lr 5
python main.py --lr 500

Nothing breaks: both reach $p \approx 1$. This is not a bug. With GRPO, mean-only or RLOO the advantages in a group sum to zero, so a step can only raise the correct answer's logit and lower the wrong ones'. For a softmax with its own logits (one question, one token, no KL penalty), $p$ can never decrease, whatever the step size. Overshooting needs shared parameters: a network where pushing up one answer also moves others, as with the MLP over prompts and positions in the project's main task. That is why E3 uses the MLP.

(d) Diversity vs. pass@1 — E4 (Thrampoulidis et al.)

Maximizing pass@1 rewards putting all probability on one answer, which kills diversity. Optimizing pass@$k$ instead has gradient

$$\nabla\, \text{pass@}k = k\,(1-p)^{k-1}\, \nabla p.$$

The weight $k(1-p)^{k-1}$ is large on prompts the model rarely solves and near zero on prompts it already solves, so effort spreads out and the policy stays diverse, at some cost to pass@1.

Try it 
python main.py -G 16
python main.py -G 16 --advantage passk -k 8

After 300 steps, GRPO reaches $p = 0.999$ with entropy $0.01$: the policy has collapsed onto one answer. Pass@8 shaping stops at $p \approx 0.55$ with entropy $1.56$. That is enough for pass@8 to be near 1, so it stops pushing. On a single question this is all you can see; the project measures it across many prompts, where diversity matters more.

7How this becomes the project

The theory assumes exact gradients, infinite groups and simple policies. Real training uses noisy samples, small $G$ and neural networks. The project's synthetic task extends the playground: prompts become feature vectors, the softmax becomes a small MLP, and each answer has $L$ tokens, with a reward of 1 only if all of them are correct. Because $p$ is still exact, you can turn one knob at a time and see where reality departs from theory.

Answer length $L$, vocabulary $K$Sparsity: $p_0 = K^{-L}$E1, E5
Group size $G$Informative groups, finite-$G$ effectsE1, E2

E6 then checks whether the same curves appear on a real 0.5B-parameter LLM (Qwen2.5-0.5B-Instruct on GSM8K).
